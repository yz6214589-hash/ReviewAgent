# 输入文档分类及索引

> 版本：v1.0 ｜ 生成日期：2026-09-29
> 适用范围：`project/25年`、`project/26年`、`project/数据` 三个目录共 **46 份**业务文档
> 用途：指导评审智能体（review-agent-v2）的规则输入、知识库构建与测试/训练数据选型

---

## 一、概述

依据评审智能体的数据角色分工，将全部输入文档划分为三类：

| 类别 | 定位 | 在 Agent 系统中的去向 |
|---|---|---|
| **A 类：业务分析 / 系统规则输入** | 含业务流程、功能需求、规则定义等核心业务逻辑 | 规则引擎、Prompt Schema、字段抽取模板、评分逻辑 |
| **B 类：知识库沉淀** | 含普适性知识、最佳实践、常见问题解决方案等可复用内容 | RAG 知识库（向量化检索、Few-shot 示例库） |
| **C 类：测试 / 训练数据** | 满足数据质量要求（格式规范、场景覆盖全面、标注准确） | 评测集（Benchmark）、SFT 训练对（输入-输出配对） |

分类原则：**输入/输出分离**（会议记录是输入素材，专家意见与纪要是输出样例）、**会审/函审分离**、**保密数据隔离**、一份文档允许"主分类 + 辅分类"。

---

## 二、三类文档的定义与判定标准

### A 类：业务分析 / 系统规则输入

判定标准（满足其一即可纳入候选）：

1. **含显式规则定义**：评分量表、权重分配、通过/否决条件、等级划分；
2. **含结构化字段 Schema**：固定的采集/登记字段（如"项目名称 / 指标类别 / 专家姓名 / 专家意见"），可直接转化为抽取模板或表单定义；
3. **含业务流程定义**：评审组织方式（会审分组、函审流程）、分类体系（如"关键核心技术攻关 21 项"）、环节流转规则。

### B 类：知识库沉淀

判定标准：

1. **知识密度高**：包含专家对技术路线的关注点、质疑角度、评审口径等可迁移知识；
2. **普适性 / 可复用**：内容不绑定单一项目，对新项目评审有参考价值（如意见写作范式、纪要结论写法）；
3. **可检索性**：主题边界清晰，切分后片段语义自洽，适合向量化与按项目/主题检索。

### C 类：测试 / 训练数据

判定标准（须同时满足）：

1. **格式规范**：可程序化解析（docx/xlsx 标准格式），文本完整无大面积缺损；
2. **场景覆盖全面**：覆盖不同组别、不同日期、不同项目类型、会审与函审两种模式；
3. **标注准确 / 可配对**：能构成"输入（会议记录）→ 输出（专家意见 / 纪要）"的训练对，或字段级标注（结构化表格）准确可信。

## 三、筛选流程

```
清点登记 → 格式探测 → 内容抽样 → 三维打分 → 确定主辅分类 → 登记索引
```

1. **清点登记**：遍历三个来源目录，登记文件名、大小、格式，共 46 份；
2. **格式探测**：docx/xlsx 按 zip 解包验证可读性；.xls 检测文件头（PK/OLE）区分新旧格式；txt 检查是否为空；
3. **内容抽样**：提取 `word/document.xml`（docx）/ `xl/sharedStrings.xml`（xlsx）纯文本，统计字符数、表格数，抽读首尾段落判断文档性质；
4. **三维打分**：对每份文档按 A/B/C 三个适配维度打分（见第四节），得分最高的为主分类，次高且达标的为辅分类；
5. **登记索引**：记录主/辅分类、质量等级、质量风险与建议用途，形成第五节总索引。

## 四、评估方法与评分维度

### 4.1 评分维度

| 维度 | A 类适配度 | B 类适配度 | C 类适配度 |
|---|---|---|---|
| 1 | 结构显式性（有无固定字段/模板） | 知识密度（可迁移知识占比） | 格式规范性（可解析、完整） |
| 2 | 规则完备性（规则是否成体系） | 普适性（跨项目复用价值） | 配对完整性（能否构成输入-输出对） |
| 3 | 权威性（是否为官方模板/定稿） | 可检索性（主题边界清晰度） | 覆盖度（组别/日期/项目类型） |
| 4 | — | — | 标注质量（字段/结论准确性） |

### 4.2 质量等级

| 等级 | 含义 |
|---|---|
| **高** | 内容完整、结构清晰，可直接使用 |
| **中** | 主体结构可用，存在局部缺损（空白项、转写错字等），需清洗 |
| **低** | 格式或内容有阻断性问题，需先处理再评估 |
| **—** | 无有效内容，不参与分类 |

## 七、对 Agent 系统构建的指导

| 分类 | 系统落点 | 具体用法 |
|---|---|---|
| **A 类**（12 份） | 规则引擎 + Prompt Schema | #19 评分量表 → 评分模块权重配置；#10–#15 反馈表 → 意见采集表单与抽取字段定义；#4–#6、#42 意见矩阵/函审清单 → 结构化解析模板与项目分类体系；#44–#46（辅） → 纪要生成模板 |
| **B 类**（14+3 份） | RAG 知识库 | 按"组别 / 项目 / 主题"三级元数据切分向量化；意见与纪要作为写作范式示例库（Few-shot）；会议记录中"跳高指标研讨"等片段作为专家关注点专题知识 |
| **C 类**（16+ 份） | 评测集 + SFT 训练对 | 训练对：会议记录（输入）→ 意见输出/专家意见（输出），按组配对（25年 3 对、26年 3 组对、项目纪要 8 对）；评测集：留出 1–2 个完整项目做端到端生成评测；结构化 xlsx 用于字段抽取准确率评测 |
| 保密隔离 | 安全边界 | #19 单独建库，仅在评分模块内受控引用 |

## 附：术语与缩写

- **会审**：专家组集中会议评审（分一/二/三组）；**函审**：专家书面函审。
- **训练对（input-output pair）**：以原始会议记录为输入、定稿专家意见/纪要为输出的监督样本。
- 字数统计口径：docx 取 `word/document.xml` 去标签后纯文本长度；xlsx 取 `xl/sharedStrings.xml` 去标签长度。
